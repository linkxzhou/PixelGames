## 1. 背景

PixelGames 的素材编译主链已经在 `steps/step-300-asset-build` 落地一套确定性像素工具（`pxl-core` / `pxl-format` / `pxl-ops` / `pxl-export` / `pxl-cli`→二进制名 `step-300`）。并行地，仓库以只读参考形式保存了完整的 Aseprite 源树于 `thirdparty/aseprite/`。

业务需求不是「在引擎里嵌一个像素编辑器」，而是：

1. 用 **Rust + CLI** 对齐 Aseprite 的**文档语义与批处理能力**（打开/改色模/滤镜/按层与标签导出/写 sheet 等）；
2. 与现有 `step-300` 子命令共存，能把 `.aseprite` 与现有 recipe / `PxlDoc` 管线对接；
3. **严格遵守 EULA**：不复制源码与专有资源，clean-room 实现。

Aseprite 自身源码分层（`src/README.md`）已明确 Level0–Level5。本版只取与无头相关的层，明确跳过 UI/桌面/Steam/updater。

## 2. Aseprite 层对应（本地核实）

| 层 | 路径（相对 `thirdparty/aseprite/`） | 本版态度 |
|---|---|---|
| L0 | `src/fixmath/`、`src/flic/`、`src/undo/`、`src/observable/`、`laf/*` | 概念参考；Rust 用标准定点数/事件按需自研；**不做** laf OS/UI |
| L2 doc | `src/doc/`（MIT LICENSE 本地存在） | **核心对齐对象**：Document/Sprite/Layer/Cel/Image/Palette/Tag/Slice/Grid… |
| L2 ui | `src/ui/` | **跳过** |
| L3 dio | `src/dio/`（`.aseprite` 编解码） | **核心**：优先读，写紧随 |
| L3 filters | `src/filters/` | **核心**：无头滤镜命令 |
| L3 render | `src/render/` | **核心**：合成与量化/抖动辅助 |
| L3 view | `src/view/`（timeline range 抽象；其 README 指向 EULA） | 只取「帧/层范围」概念，不做视图 |
| L4 app | `src/app/`，尤其 `src/app/cli/`、`src/app/file/`、`src/app/commands/` | CLI 开关与文件格式注册表作**行为对照**；commands 中与 UI 耦合者跳过 |
| L4 desktop / L5 main | `src/desktop/`、`src/main/` | **跳过** |
| 旁路 | `src/psd/`、`src/tga/`、`src/steam/`、`src/updater/`、`src/net/` | tga/psd 作可选 IO；steam/updater/net **跳过** |

公开文件规格：`thirdparty/aseprite/docs/ase-file-specs.md`（Header magic `0xA5E0`，色深 32/16/8 等）。公开 CLI：https://www.aseprite.org/docs/cli/ ，与本地 `src/app/cli/app_options.h` / `app_options.cpp` 开关名一致（`--batch`、`--save-as`、`--sheet`、`--tag`、`--list-layers` 等）。

## 3. 目标产品形态（CLI-first）

### 3.1 主方案（冻结）

- **库**：在 `steps/step-300-asset-build/` 下新增一组 `pxl-ase-*` crates（见 §4），不碰 `games/`。
- **命令面**：扩展现有 `pxl-cli`（Cargo 包名 `pxl-cli`，二进制名 **`step-300`**）增加子命令组：

```text
step-300 ase --batch <files...> [与公开 CLI 对齐的 flags...]
step-300 ase inspect <file.aseprite>
step-300 ase convert ...
step-300 ase filter ...
```

- **共存**：现有 `gen` / `op` / `anim` / `palette` / `sheet` / `render` / `build` / `plan` 等子命令**保持不变**；`ase` 负责「文档级 / `.aseprite` 级」批处理，`sheet` 继续服务已有 `PxlDoc` 打包。
- **可选别名**：后续可加薄二进制 `pxl-ase`，内部调用同一库；不作为 M0–M8 阻塞项。

### 3.2 为何不「另起一套完全独立 CLI 替代 step-300」

`step-300` 已是五大步契约中的资产编译入口（`plan`/`build` 写 `index.json`）。另起孤岛会迫使 step-200/400 双轨。主方案把 Aseprite 对齐能力挂在同一二进制下，用子命令命名空间隔离，迁移成本最低。

## 4. 建议 crate 地图

路径均相对仓库根；**名称待 M0 冻结**，此处为架构草案：

| Crate | 职责 | 主要依赖 | 对应 Aseprite |
|---|---|---|---|
| `pxl-ase-doc` | Sprite/Layer/Cel/Frame/Image/Palette/Tag/Slice/Grid、色模式 | `pxl-core`（颜色/IndexFrame 桥） | `src/doc/` |
| `pxl-ase-io` | `.aseprite` 读写；探测；PNG/GIF/TGA/FLI 适配器 | `pxl-ase-doc`、`pxl-export`（PNG/GIF） | `src/dio/` + `src/app/file/*_format*` |
| `pxl-ase-color` | remap、量化入口、色模转换、rgbmap 概念 | `pxl-ase-doc`、`pxl-core`、`pxl-art`（median_cut 等） | `doc/palette*`、`doc/remap*`、`render/quantization*` |
| `pxl-ase-ops` | 无头编辑 op（选区/填充/变换）与现有 `pxl-ops` 桥 | `pxl-ops`、`pxl-format::Op` | `doc/algorithm/`、部分 `app/commands` |
| `pxl-ase-filters` | outline/replace/hue/convolve/median/… | `pxl-ase-doc` | `src/filters/` |
| `pxl-ase-render` | 层合成、flatten、export 用光栅 | `pxl-ase-doc` | `src/render/` |
| `pxl-ase`（facade） | 批处理流水线、与公开 CLI 语义编排 | 以上全部 | `src/app/cli/*` |
| `pxl-cli` 增量 | `Cmd::Ase(...)` | `pxl-ase` | — |

也可在早期将 `pxl-ase-color` / `filters` / `ops` 合并为较少 crate，但**逻辑边界**仍按上表验收。

## 5. 依赖顺序

```text
M0 基线与契约草图
 └─ M1 pxl-ase-doc
     ├─ M2 pxl-ase-io（.aseprite 读 → 写）
     ├─ M3 pxl-ase-color（可与 M2 后半并行）
     ├─ M4 ops + filters
     ├─ M5 render + 导出（复用/扩展 pxl-export）
     └─ M6 时间轴 tags/slices
         └─ M7 CLI 命令面
             └─ M8 steps 集成试点
                 └─ M9 可选脚本
```

`pxl-core` / `pxl-export` / `pxl-ops` / `pxl-art` 为**已有底座**，新 crate 优先调用，禁止平行复制一套 IndexFrame/PNG 编码器。

## 6. 与 steps 对照（总表）

| 能力域 | 标注 | 证据（代码核实） |
|---|---|---|
| 索引帧、调色板、描边、缩放 | 【已有·可复用】 | `pxl-core`：`frame.rs`/`palette.rs`/`outline.rs`/`scale.rs` |
| Op DSL + apply | 【已有·可复用】 | `pxl-format/src/ops.rs`；`pxl-ops` `apply_op`/`macros` |
| PNG/GIF/sheet + Aseprite **hash JSON** 导出 | 【已有·可复用】【部分】 | `pxl-export`；`sheet_json` 写 `frames`+`meta.frameTags`；**无** `.aseprite` 二进制 |
| CLI 子命令 | 【已有·可复用】【部分】 | `pxl-cli`：`gen/op/anim/palette/sheet/render/build/plan/...`；**无** `ase` 组、**无** `--batch` 文档级流水线 |
| 生成/ASCII/SVG/增强 | 【已有·可复用】（旁路） | `pxl-gen`/`pxl-svg`/`pxl-art`；非 Aseprite 对齐主线但可作导入源 |
| 多层 Document、Tag/Slice 一等公民、`.aseprite` IO、完整滤镜集、层合成 blend | 【缺失】 | `rg` 未见 ase 解码器；文档模型停在 `PxlDoc`/单帧族 |

## 7. 非目标

1. 任何 GUI / 即时绘画循环 / 快捷键表 / 多窗口。  
2. Steam、自动更新、崩溃恢复 UI、桌面缩略图扩展。  
3. 把 Lua 脚本 API 像素级复刻（见 `10`；可选）。  
4. 复制 `thirdparty/aseprite` 下任何 `.cpp/.h` 或 `data/` 资源到产品。  
5. 修改 `games/*` 或宣称 v7 NES 里程碑完成。  
6. 未跑测试就写 PASS。
