# 10 · 脚本与扩展（可选 / 后续）

> 日期：2026-11-02（Asia/Shanghai）  
> 状态：**后续**（2026-11-02 Asia/Shanghai）  
> 证据：未实现脚本宿主（M9）
> Aseprite 对应：Lua scripting（公开文档）、CLI `--script` / `--script-param` / `--shell`；源码侧 `app` 与 scripting 集成（本版不深入 UI 宿主）

## 1. 背景

Aseprite 提供 Lua 脚本与 `--shell` REPL，便于用户扩展。PixelGames 方向更偏：**Rust crate API + 确定性 CLI +（已规划未实现的）MCP**。本文件记录可选脚本宿主，避免主线范围膨胀。

## 2. 目标（可选）

1. 稳定的 Rust API：`pxl_ase` 库可被外部 crate 调用（无 UI）。  
2. 长期：嵌入式脚本（Lua 或 Rhai）调用同一 API；CLI `--script` 语义近似公开文档。  
3. 与 `pxl mcp`（`Cmd::Mcp` 现返回未实现）的关系：脚本宿主 ≠ MCP；可并存。

## 3. 非目标（主线）

- 复刻 Aseprite Lua API 表面每一个全局对象。  
- 在脚本里弹窗、读键盘、改主题。  
- 把 `--shell` 当作 M7 验收条件。

## 4. 与 steps 对照

| 能力 | 标注 | 证据 |
|---|---|---|
| Rust 库可组合 | 【部分】 | 现有 `pxl-*` 已是库；缺 `pxl-ase` |
| CLI `--json` 可被 agent 驱动 | 【已有·可复用】 | `pxl-cli` 全局 `--json` |
| MCP server | 【缺失】 | `Cmd::Mcp` 显式未实现 |
| Lua/`--script` | 【缺失】 | — |

## 5. 工作包（后续）

### M9.0 — API 稳定性层

- 导出 `open`/`save`/`flatten`/`apply` 的 rustdoc 示例。  
- **验收**：examples 目录可编译。

### M9.1 — 脚本原型

- 选 Rhai 或 Lua；证明能改一层像素并保存。  
- **验收**：一个脚本夹具；安全：无任意文件系统逃逸（沙箱策略成文）。

### M9.2 — CLI `--script`

- 对齐公开 `--script-param` 键值传入。  
- **验收**：08 矩阵该行从「后续」变为实现或继续延期说明。

## 6. 风险

- 脚本任意代码执行 → 默认沙箱、显式 `--allow-fs`。  
- API 未稳就承诺 Lua 兼容 → 先冷 Rust API。

## 7. 依赖

- 依赖：M7+ 库表面稳定。  
- 不阻塞 09 试点。


## 8. 与 agent / MCP 的边界

- 今日 agent 应继续用 `step-300 --json ...` 驱动；`ase` 子命令同样输出 JSON 摘要。  
- `pxl mcp` 仍是独立未实现项（`lib.rs` 明确 usage 错误）；不要在 M9 之前把脚本宿主冒充为 MCP 完成。  
- 若未来 MCP 暴露 `ase.open` tools，应调用同一 `pxl_ase` API，避免两套语义。

## 9. 安全清单（若做脚本）

1. 默认禁止访问仓库外路径。  
2. 默认禁止网络。  
3. 循环步数上限。  
4. 内存像素缓冲上限对齐 `MAX_CANVAS` / 文档预算。  
5. 所有脚本运行写入 audit log（stderr 或文件），便于 CI。

## 10. 验收（仅当启动 M9）

- 示例脚本：打开夹具、替换一色、保存、退出码 0。  
- 恶意脚本试图写 `/etc` 被拒。  
- 未启动 M9 前，本文件所有项保持「后续」，不得标 PASS。
