# 02 · 颜色与调色板

> 日期：2026-11-02（Asia/Shanghai）  
> 状态：**部分完成**（2026-11-02 Asia/Shanghai）  
> 证据：`pxl-ase::color` convert/remap/quantize；CLI `--color-mode`
> Aseprite 对应：`src/doc/palette*`、`remap*`、`rgbmap*`、`sort_palette*`；`src/render/quantization*`、`dithering*`；`src/doc/file/{gpl,pal,act,col,hex}_file*`；CLI `--palette` / `--color-mode` / `--dithering-*`

## 1. 背景

批处理高频场景：换色板、RGB↔Indexed、量化、抖动、按 ramp 着色。Aseprite CLI 用 `--palette`、`--color-mode`、`--dithering-algorithm`、`--dithering-matrix` 表达。PixelGames 已有较强的**索引调色板**与艺术向量化，但缺少文档级色模状态机与 `.aseprite` 内嵌 palette chunk 语义。

## 2. Aseprite 对应模块

| 主题 | 路径 | CLI / 规格 |
|---|---|---|
| Palette 对象 | `doc/palette.h`、`palette_io.*` | 帧可有多 palette；规格见 ase-file-specs |
| Remap | `doc/remap.h` | 索引重排 |
| RgbMap | `doc/rgbmap*.h` | 最近色查找 |
| Sort | `doc/sort_palette.*` | 调色板排序 |
| 外部 palette 文件 | `doc/file/gpl_file.*` 等 | GPL/PAL/ACT/… |
| 量化 / 抖动 | `render/quantization.h`、`dithering_algorithm.h`（ordered/error diffusion 等） | `--dithering-algorithm none\|ordered\|old`；matrix `bayer2x2/4x4/8x8` |
| 色模 | `doc/color_mode.h` | `--color-mode rgb\|grayscale\|indexed` |
| App 色彩 | `app/color_spaces.*` 等 | 完整 ICC/UI **非目标**；仅保留「能 CLI 化」的转换 |

## 3. 目标

1. 文档级 `Palette`（最多 256）与 `Remap` 表。  
2. CLI：`--palette <file>` 应用到当前文档（对齐公开语义）。  
3. `--color-mode` 转换；RGB→Indexed 支持 none/ordered 抖动与 bayer 矩阵。  
4. 量化：复用 `pxl-art` median_cut / map_to_palette；缺口补齐。  
5. `step-300 palette` 子命令与 `ase` 色板操作的职责划分写清。  
6. 可读 GPL（优先）等常见 palette 文件（clean-room）。

## 4. 非目标

- 完整显示器色彩管理 / ICC 编辑 UI。  
- 复制 Aseprite 扩展里的专有 dither matrix 资源文件。  
- 保证与 Aseprite 抖动像素级 bit-identical（允许算法等价 + 文档说明差异）。

## 6. 工作包 / 里程碑

### M3.0 — 色模状态机

- `Sprite` 上色模切换的前置条件（有无透明索引、层一致性）。  
- **验收**：非法转换返回结构化错误；测试覆盖 RGB→Gray→RGB 往返容差策略书面化。

### M3.1 — Remap 与 `palette swap` 对齐

- 统一 remap 表达；`step-300 palette swap` 可作用于 `AseDoc` 桥接路径。  
- **验收**：同一 map 文件对 `PxlDoc` 与单层 `AseDoc` 结果一致。

### M3.2 — 量化 + 抖动 CLI

- 实现 `ase --color-mode indexed --dithering-algorithm ordered --dithering-matrix bayer8x8`。  
- 复用 `pxl-art`；缺 bayer8 则补测。  
- **验收**：公开文档用例可跑；与 Aseprite 输出允许非 bit-identical，但索引色数/尺寸一致。`NOT_ASSESSED` 直至对比报告提交。

### M3.3 — 外部 palette 文件

- 优先 GPL；其余格式按需。  
- **验收**：fixture 往返；失败路径有码。

## 7. 与现有 `palette` 命令共存

| 场景 | 用哪个 |

## 11. 附录：与公开 `--color-mode` 用例的对照

公开文档示例（语义目标，非已实现）：

```bash
step-300 ase -b idx.aseprite --color-mode rgb --save-as rgb-output.png
step-300 ase -b rgb.aseprite --dithering-algorithm ordered --dithering-matrix bayer8x8 --color-mode indexed --save-as idx-output.png
```

实现时应用同一输入夹具分别跑本工具与（可选）本机 Aseprite，比较：尺寸、色模、索引色数量；像素 hash 允许不同并写入差异报告。无 Aseprite 二进制时，仅第一项机器验收，人工对比列 `NOT_ASSESSED`。

## 12. 附录：`pxl-core` 调色板限制清单（实施必读）

来自 `pxl-core/src/lib.rs` 与 `palette.rs` 的静态事实：

- 核心条目可至 256；`index 0` 为透明约定（与校验逻辑一致处须保持）。  
- 文本矩阵编码：`MAX_TEXT_COLORS`（`check_text_encodable`）——导入 256 色 ase 再进 ASCII/文本配方时必失败或需降色。  
- `palette ramp` CLI 默认 `max=36`（`PaletteCmd::Ramp`）——与文档 256 色并存时，UI/帮助须写清「艺术 ramp 扩展」≠「ase 文档容量」。

## 13. 附录：量化入口候选

| 入口 | 路径 | 用法 |
|---|---|---|
| `median_cut` | `pxl-art/src/quantize.rs` | RGB 采样 → 调色板 |
| `map_to_palette` | 同上 | RGBA 缓冲 → 索引；`dither` 参数 |
| `LabPalette::nearest` | 同上 | Oklab 最近色 |
| `ramp_palette` | `pxl-art/src/palette.rs` | 扩展阴影高光 |

Aseprite `PaletteOptimizer` / `DitheringAlgorithm` 仅作概念名参考，不符号级绑定。
