# 参考素材盘点与 pxl 对照

浅克隆在仓库外的 `/tmp/ref-art`，没有把这些仓库或它们的图提交进来。文件名普查用的是 `git ls-tree`（全量）。像素尺寸和调色板计数来自检出的代表文件；Terraria 那 12703 张 PNG 只对 318 张做了尺寸抽样，正文会标明。对照图只放在 artifacts，不进 git。

`pxl` 现在能稳定产出的是：有限调色板索引图、`shapes`（矩形、圆、线、像素矩阵）、Bollinger 蒙版、`noise-tile`（dirt / grass / sand，本次加上 ore）、整数 op（平移、错行、翻转、旋转 90°、换色、明暗、描边、溶解、patch）、动画宏，以及纸娃娃 `parts`。任意角度旋转仍然拒绝。默认 QA 要求角色框占画布 20%–95%、连通块 ≤ 8、孤立像素 ≤ 4、循环动画相邻帧差异 1%–35%。满铺 tile 的帧从这次起不做角色框检查，只查索引是否落在调色板里。

下面每类素材用三档：

- **现在能做**：现有生成器或 op 就能写出同尺寸、同色数级的原创图。
- **要扩展**：算法缺口明确，但仍然是索引像素，不必上 3D 或手绘模型。
- **不可行**：缺的是绘画细节、网格光照或运行时系统，靠再加几个 op 补不上。

十个原创配方在 `examples/reference/<name>/recipe.json`。像素都是 shapes、噪声和 op 写的，没有描参考图。

## NoelFB/Celeste

这个仓库不是商业版 Celeste。MIT 只覆盖代码。光栅只有 PICO-8 经典版四张图，外加 `Player.cs`。

| 文件 | 尺寸 | 不透明色 | 类别 |
|---|---|---|---|
| `Source/PICO-8/Graphics/atlas.png` | 128×88 | 15 | 8×8 精灵表，约 16×11 格。第 0 行后半是侧视跑步 |
| `font.png` | 120×12 | 2 | 单行字形 |
| `logo.png` | 40×10 | 10 | 标志 |
| `consolebg.png` | 320×180 | 35 | 控制台底图，色数已经超出小精灵 |

动画类型：图集里的少量关键帧（跑、跳、攀）。头发链、冲刺残影、粒子是运行时代码，不在 PNG 里。没有立绘、没有独立粒子图集。

| 类别 | 判定 | 原因 |
|---|---|---|
| 8×8 角色跑动 | 现在能做 | `shapes` + 逐帧 `patch_pixels`。见 `celeste-run` |
| 尖刺、坡道、弹簧这类 8×8 机关 | 现在能做几何，要扩展方向和自动拼接 | 单格能画。四向和邻接变体要 autotile |
| 8×8 字形 | 现在能做少量字，要扩展才有整套字库 | 矩阵能写字母。120×12 的完整间距和字宽要字体生成器 |
| 控制台底图、标志 | 不可行 | 35 色插画，不是程序几何 |
| 头发物理、粒子 | 不可行（作为离线帧） | 那是每帧跟随速度的链，不是 4 帧宏 |

## YouhuaUncle/Pixel-art-3D-to-2D-rendering-in-Godot

0 张光栅。这是 Godot 编辑器插件：导入 FBX/glTF，选相机和 AnimationPlayer，用 `pixelize.gdshader`（默认 `pixel_count = 64`）把 3D 画面量化成纹理，可换法线材质，再导出单帧或序列。产物在用户工程里，不在这个仓库里。

| 类别 | 判定 | 原因 |
|---|---|---|
| 像素化的 3D 静帧 / 转身 | 不可行 | `pxl` 没有网格、相机、灯光。`shade` 只沿 ramp 推一格，不是法线 |
| 若已有一张 RGBA 烘焙 | 要扩展 | 缺一个确定性的索引量化器：把外部烘焙吸到固定调色板。那一步仍然不是 3D 渲染 |

对照图用的是 numo9 的 `bank3d` 烘焙裁切，因为这个 Godot 仓库没有帧。

## 仍然做不到的，以及要加什么

本次代码只加了两处，都保持确定性和整数运算：

- `noise-tile` 的 `ore`。宿主 ramp 是 `stone` 或 `host`，矿脉 ramp 是 `ore`（或显式 `--ramp`）。矿只画在内圈，外圈仍走原来的接缝检查。
- `validate --rules default` 对 sheet 里登记成 tile 的帧跳过角色框、连通块和孤立像素。索引检查还在。打包时只有 `meta.kind = tiles` 的文档算 tile，没有动画的普通精灵不再被误当成 tile。

下面这些不是再调配方能解决的：

| 缺口 | 需要的扩展 | 为什么现在不行 |
|---|---|---|
| 草地压边、矿的裂缝、耕地、墙 | blob 47 或 Wang 16 autotile，加接缝测试 | 路线图 M3。噪声只能保证对边 ramp 距离 ≤ 1 |
| 整套字体、九宫格框、按钮态 | `gen font` 或字形 spec，加上 9-slice 绘制 | 现在只能手写几行像素矩阵 |
| 头发、披风、史莱姆挤压 | 沿骨骼或区域的 squash，且不要把孤立像素撑破 QA | `squash` 和 `row_shift` 已有，但 8×8 上很容易剪掉像素或差出 35% |
| 弹幕花样（骨头、环、自机狙） | 弹幕宏：沿整数轨迹放若干精灵，而不是只 `spin_projectile` | 旋转只能 90° |
| 四向手绘 NPC、长攻击 | 更多纸娃娃部位可以逼近 | 每帧轮廓不同的手绘仍然要外部图 |
| 64×64 立绘、季节表情、商业版角色 | 不做 | 色数和笔触都不是程序几何。描图会碰到版权 |
| 3D 转 2D、法线、转身表 | 网格渲染，或「外部 RGBA 烘焙 → 固定调色板」的量化器 | `shade` 不是灯光。Godot 插件的像素化发生在 GPU 上 |
| 任意角度 | 已明确拒绝，等 cleanEdge 一类算法 | `rotate` 现在返回语义错误 |
| 加色粒子、全屏 2 色边框 | 混合模式和大于 64px 的画布 | `MAX_DIM` 是 64，也没有加色 |

## v2（`e6d38a7` 上重做的十张配方）

引擎停在 `e6d38a7`，生成器、op 和 QA 都没有改。`crates/pxl-cli/tests/cli.rs` 里 `misspelled_macro_argument_fails_the_build` 原先把 meadow-slime 配方里的 `idle_rumble(steps=2, amp=1)` 改成拼错的参数；配方换成 `blink` 之后，测试改成把 `blink(...)` 的 `x` 写成不存在的 `step`，仍然要求构建以 exit 3 失败，错误信息里带这个参数名。这是测试夹具，不是引擎修复。

旧列用提交 `6868c64` 的二进制重放当时的配方。新的 `shade` 只沿指定 ramp、或只沿「只属于一条 ramp」的索引移动；用新引擎重放旧箱子会把当时共享的索引留在原地，对不上 PR #1 的图。

这次配方实际用上的新行为：

- `shade` 的 `ramp`：作物叶子、树冠、箱子木身、板条箱的顶面和两个立面各走自己的色阶。板条箱的左立面、右立面、顶面、金属锁四条 ramp 不再共用索引，所以右立面不会被顶面的高光索引带亮。
- `palette_swap` 的 `ramp:name+1`：心每两帧沿 heart 升一档；板条箱顶面闪一档。尖刺高光是 `4->5`，四向用 `rotate90`，高光跟着尖端转。旋转前不再做 shade，否则朝向会一边亮一边暗。
- `blink`：对话框光标收成纸色；史莱姆在休息姿势上闭眼。闭眼是另一条动画，不插进跳跃。
- 手写矩阵：跑步四姿势、作物五阶段、地形六张图章、箱子盖、史莱姆挤压。树冠仍是圆，但加了分叶缝、弯干和果实；风只 `row_shift` 树冠几行。

故意没用的：

- `death_dissolve` 最后一帧是空的，默认角色框检查不过，心的碎裂没有做。
- `spin_projectile` 把整张画布转 90°，心和弹会一起转。
- `pulse_glow` 是整精灵升一档。心的脉冲改成显式 `ramp:heart+1`，再在下面补一颗人字弹，帧差停在 16×16 的 89 像素以内。
- `texture` / Bollinger 会铺程序噪声，这轮的材质是手写色阶。
- 8×8 噪声 tile 的 cell 是 4，画面是大色带。满铺 8×8 的不透明图角色框是 100%，过不了默认 QA；tile 才会跳过这项，而 shapes 精灵不能标成 tile。地形改成 8×9 的手写图章，最后一行留空（约 88.9%）。没有 autotile，图章也不能无缝拼接。
- 8×8 跑步的帧差上限是 22 像素（0.35×64）。四帧已经用到 21，没有再加 shade。
